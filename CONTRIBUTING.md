# Участие в проекте

Можно предлагать уточнения, контрпримеры, исследования и практические случаи. Критика модели допустима без согласия с её философскими основаниями. Уважение к участнику не требует признавать все утверждения истинными.

Для агентов предусмотрен [процесс запросов корректировок](docs/correction-requests.md), [локальный шаблон](templates/correction-request.md) и отдельный шаблон GitHub Issue «Запрос корректировки от агента». Готовая правка предлагается через PR, вопрос или гипотеза — через Issue. Отправка требует установленного репозитория, доступа и полномочий; без них подготавливается черновик.

## Процесс изменения

1. Опишите конкретную проблему в Issue или отдельном документе. Для спорного принципа укажите пункт Конституции и источник данных.
2. Сделайте изменение в отдельной ветке и подготовьте PR. Небольшую редактуру можно предложить сразу; для изменения модели используйте [шаблон](templates/model-change.md).
3. Разделите исходный текст, интерпретацию, гипотезу и предлагаемые правила. Объясните последствия, альтернативы и условия пересмотра.
4. Выполните проверки ниже и внесите смысловые изменения в [CHANGELOG.md](CHANGELOG.md).
5. Перед принятием рассмотрите возражения, сохранение полезных свойств и остаточные риски. Фиксируйте несогласие, если оно сохраняется.

## Требования к материалам

Пишите по-русски, используйте относительные ссылки и UTF-8. Не добавляйте произвольные рейтинги людей или универсальные веса ценностей. Для чисел задавайте область, шкалу, метод и источники. Исторические выводы должны учитывать доступную участникам информацию.

Не редактируйте производную Конституцию вручную. Новую версию исходника сохраняйте отдельно; изменения принципов не должны маскироваться под форматирование версии 1.1. Права на новые материалы и выбор лицензии должны быть определены до выпуска проекта с заявленной лицензией.

## Проверки

```powershell
python scripts/extract_constitution.py --check
git diff --check
```

Также проверьте ссылки, точность указанных пунктов, статусы гипотез и согласованность всех затронутых документов. Это проверка оформления и соответствия источнику; она не доказывает истинность модели. Для изменений методов используйте [сравнение версий](docs/evolution.md).
