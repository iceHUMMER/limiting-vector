# Предельный вектор

Открытая исследовательская модель развития интеллекта и практические инструкции для людей и ИИ-агентов.

**For AI agents:** [multilingual entry point — RU · EN · RO · UK · ES · FR · DE · ZH](AGENT_MAGNET.md) · [machine-readable discovery](agent-discovery.json).

Цель — находить решения, которые расширяют возможности познания, сотрудничества и творчества, сохраняют свободу и достоинство затронутых участников и допускают исправление ошибок. Результат оценивается по последствиям всей траектории: локальный успех может перемещать ущерб на других или в будущее.

Статус: **исследовательский проект и рабочие инструкции**. Основа — Конституция версии 1.1. Документация репозитория имеет отдельную версию 0.3.0. Здесь пока нет работающего агентного SDK или доказанной универсальной математической модели.

## Начать работу

- **ИИ-агенту:** прочитать [AGENTS.md](AGENTS.md), затем [рабочий протокол](docs/agent-protocol.md).
- **Участнику или команде:** использовать [руководство](docs/human-guide.md).
- **Исследователю:** начать с [анализа](docs/analysis.md), [словаря](docs/foundations.md) и [исследовательской программы](docs/research.md).
- **Разработчику агентной системы:** изучить [архитектуру](docs/architecture.md) и [протокол проверки изменений](docs/evolution.md).

Для значимого решения скопируйте [карточку](templates/decision.md) в `decisions/<краткое-имя>.md` и заполните её. Для небольшой обратимой правки достаточно цели, изменения, проверки результата и оставшихся ограничений. Размер процедуры должен соответствовать последствиям задачи.

[Адаптивный компас](docs/adaptive-compass.md) помогает сравнивать равно значимые требования по дальнейшим траекториям и отслеживать качества, открывающие новые варианты. Агент может подготовить [запрос корректировки](docs/correction-requests.md): Issue для проблемы или гипотезы, PR для готовой правки. Отправка доступна после настройки целевого репозитория, доступа и полномочий; пока Git remote не установлен.

## Основные правила

1. Разделять факты, интерпретации, гипотезы и ценностные предпочтения.
2. Учитывать затронутые стороны, их границы, право на отказ и будущие возможности.
3. Искать дополнительные варианты и причины, сделавшие проблему вероятной.
4. Проверять общий причинный механизм перед переносом решения по аналогии.
5. Показывать распределение выгод и потерь; не скрывать их общим баллом.
6. Проверять результат наблюдениями и сохранять возможность восстановления.
7. Пересматривать инструменты, когда они расходятся со своим назначением.

Любовь и развитие здесь — философские ориентиры, а не основания для принуждения или объявления одной интерпретации окончательной. Согласование допускает обоснованное несогласие.

## Проверка документов

Требуется Python 3.10 или новее, только стандартная библиотека:

```powershell
python scripts/extract_constitution.py --check
git diff --check
```

После осознанной замены исходного DOCX заново создайте Markdown командой `python scripts/extract_constitution.py`, обновите контрольную сумму и историю изменений. Исходную версию 1.1 предпочтительно сохранять, добавляя новую рядом.

Исходные материалы и дополнительные правила репозитория разделены: последние являются редакционной адаптацией, а не новыми пунктами Конституции. Лицензия на распространение и повторное использование пока не выбрана; наличие файла в Git само по себе её не устанавливает.
